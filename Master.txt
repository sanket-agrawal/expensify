# PRODUCT
3 friends go on a trip. Everyone pays for different things (hotel, food, fuel, tickets). We upload bill photos, log who paid and who shared the cost, and the app shows each person's share and the minimum payments needed to settle up. Think "Splitwise, but with a chill holiday feel". Primary use is on mobile, so design mobile-first and make desktop good too.

# TECH STACK (non-negotiable)
- Frontend: Vue 3 (Composition API, `<script setup lang="ts">`), TypeScript strict mode, Vite, Vue Router, Pinia
- Styling: Tailwind CSS with custom design tokens (no component library that makes it look generic; headless primitives are fine)
- Icons: `lucide-vue-next`
- Backend: Vercel Serverless Functions in `/api` (TypeScript), no separate server
- Database: MongoDB via the official `mongodb` driver (no Mongoose). Connection string from `MONGODB_URI`. Cache the client on `globalThis` to avoid connection exhaustion in serverless.
- File storage: Google Cloud Storage, private bucket. Photos are uploaded **directly from the browser via V4 signed upload URLs** (Vercel functions have a ~4.5MB body limit, so never proxy images through the API). Reads use short-lived signed GET URLs. Client-side compress images (max ~1600px, JPEG ~0.8) before upload.
- Validation: Zod, shared schemas between frontend and API (`/shared`)
- Deploy: Vercel. Include a correct `vercel.json` (SPA fallback rewrite, `/api` untouched)
- Env vars: `MONGODB_URI`, `MONGODB_DB`, `GCS_BUCKET`, `GCP_SERVICE_ACCOUNT_JSON_BASE64`. Provide `.env.example`. Never commit secrets.

# CORE FEATURES

## 1. Trips and people
- Create a trip: name, optional emoji/cover, currency (default INR), participants (2 to 10 names)
- Generate a long unguessable `accessToken`. The trip URL is `/t/:token`
- First visit on a device: "Who are you?" picker of participants, stored in localStorage as `currentParticipantId`. Can be switched from the profile menu.
- All API routes require the trip token. Reject otherwise.

## 2. Add expense (the most important screen)
Fields: title, amount, date, category (auto-detected, editable), paid by (single participant), split among (multi-select, default all), split mode, notes, bill photos (multiple).
- **Split modes:** Equal (default), Exact amounts, Percentages. Validate that totals match and show the live remainder.
- **Bill upload:** drag/drop or camera capture on mobile, with thumbnails, upload progress, remove, retry, and a fullscreen preview lightbox.
- **Auto icon and category:** as the user types the title, instantly pick an icon and category with a pure client-side keyword matcher in `src/lib/categoryMatcher.ts`.
  - Normalise text (lowercase, trim, strip punctuation), match against keyword lists (include Indian context: "chai", "dhaba", "thali", "petrol", "toll", "auto", "ola", "uber", "homestay", "resort", "ticket", "entry fee", "beer", "wine", "club", "cab", "bike rental", "scooty", etc.). Use fuzzy match for minor typos.
  - Categories: Stay, Food, Drinks, Coffee/Chai, Groceries, Fuel, Transport, Flights, Train/Bus, Toll/Parking, Activities, Tickets, Shopping, Nightlife, Medical, Tips, Misc.
  - Each category has a lucide icon plus a soft tinted colour chip. Show the detected icon animating in as the user types. Allow manual override via a small picker.
  - Unit test the matcher (Vitest) with at least 40 phrases.

## 3. Money logic (critical, test it)
- Store all amounts as **integers in minor units** (paise), never floats
- Equal split with remainder: distribute leftover paise deterministically (first N participants get +1)
- Balance per person = total paid - total owed
- **Settle-up:** compute the minimal set of transfers with the greedy creditor/debtor matching algorithm. Put this in `shared/settlement.ts` as pure functions
- Write Vitest tests for: even split, uneven remainder, custom splits, percentage splits, someone excluded from an expense, and everyone already settled
- Support recording a "settlement payment" (A paid B ₹X) that updates balances

## 4. Screens
1. **Home / Trips**: list of trips on this device (from localStorage) plus Create Trip
2. **Trip dashboard**: hero card with total spent, "you owe / you are owed" summary, per-person balance cards, and a category breakdown (simple donut or bars, hand-built with SVG or a tiny lib)
3. **Expenses list**: grouped by date, each row has category icon, title, payer, amount, a bill-photo indicator, and your share. Filters by person and category. Search.
4. **Expense detail**: photos gallery, split breakdown, edit/delete
5. **Add/Edit expense**: as above
6. **Settle up**: the minimal transfers list ("Rahul → Sanket ₹1,240"), a "Mark as paid" action, and a UPI deep-link/copy-text helper (`upi://pay?...` is optional, copy summary text for WhatsApp is required)
7. **Share summary**: generates a clean text summary to copy/share to WhatsApp

## 5. Edge cases to handle
Deleting an expense (soft delete, with undo toast), editing an expense after settlement, empty states, offline/slow network toasts, double-submit prevention, large photos, failed uploads (retry), invalid token page, trip not found.

# DATA MODEL (MongoDB)
`trips`: _id, name, emoji, currency, accessToken (unique index), participants[{id, name, colorKey}], createdAt
`expenses`: _id, tripId (index), title, amountMinor, date, categoryKey, paidBy (participantId), split{mode, shares[{participantId, amountMinor}]}, notes, photos[{objectKey, contentType, size}], createdBy, createdAt, updatedAt, deletedAt
`settlements`: _id, tripId, from, to, amountMinor, date, createdAt
Add the indexes. Store GCS **object keys**, not public URLs.

# API (Vercel functions, RESTful, all Zod-validated, consistent error shape `{ error: { code, message } }`)
- `POST /api/trips`, `GET /api/trips/[token]`
- `GET/POST /api/trips/[token]/expenses`, `PATCH/DELETE /api/trips/[token]/expenses/[id]`
- `POST /api/trips/[token]/uploads/sign` → returns signed PUT URL and objectKey (validate content type, max size 10MB, key namespaced by tripId)
- `GET /api/trips/[token]/photos/sign?key=` → signed GET URL
- `GET/POST /api/trips/[token]/settlements`
Keep a thin `api/_lib/` for db, gcs, auth, errors, and validation.

# DESIGN DIRECTION (very important)
Must feel like a **premium, chill holiday app**, polished like Splitwise/Airbnb, and must NOT look like a generic AI-generated template.

- **Mood:** golden-hour beach, calm sea, relaxed. Airy, lots of whitespace, soft depth.
- **Palette (tokens in Tailwind config + CSS variables):**
  - Sand background `#FBF7F0`, card white `#FFFFFF`, ink `#1F2A33`, muted `#6B7A86`
  - Primary lagoon/teal `#1FA3A3`, deep sea `#0E5A6B`, accent coral `#FF7A59`, sunshine `#FFC857`, seafoam `#BFE9DD`, sky `#CFE8F5`
  - Positive (owed to you) = seafoam-teal, negative (you owe) = coral. Avoid harsh red/green.
  - Provide a dark mode ("night at the beach": deep navy `#0B1D26`, not pure black).
- **Do NOT use:** purple/indigo gradients, generic glassmorphism blobs, default Tailwind blue buttons, emoji-as-design, stock "SaaS landing" layouts.
- **Typography:** display font **Fraunces** (soft, characterful serif) for headings and big numbers; **Plus Jakarta Sans** for UI text; tabular numerals for all money. Load via `@fontsource` (self-hosted, no Google Fonts request).
- **Shape and depth:** generous radii (16 to 24px), soft layered shadows with a teal tint, subtle paper/grain texture on the background, a wavy SVG divider on the dashboard hero, a gentle sun/waves illustration on empty states (hand-built SVG).
- **Motion:** purposeful and calm: spring-ish transitions, count-up on totals, icon pop-in on category detection, page transitions, skeleton loaders. Respect `prefers-reduced-motion`.
- **Mobile:** bottom tab bar, a floating "+ Add expense" button, thumb-reachable actions, bottom sheets instead of modals, safe-area insets.
- **Components to build once and reuse:** Button, IconChip, Avatar (coloured initials), MoneyText, Card, BottomSheet, Toast, EmptyState, Skeleton, SegmentedControl, PhotoGrid, Lightbox.
- Accessibility: AA contrast, focus rings, labelled inputs, keyboard navigable.
